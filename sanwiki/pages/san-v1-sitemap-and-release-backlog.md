# SAN Wiki v1 Sitemap and Release Backlog

SAN Wiki v1 is a bounded reader release, not a declaration that every archived note has been processed. Its purpose is to make the current strongest, source-governed account useful now while leaving a visible route for continuing work.

## Current candidate core

The governed candidate core is assembled from:

- 61 registered SAN concepts;
- 64 reviewed source maps;
- orientation, chronology, correction, evidence, glossary, authorship, safety, and release-governance pages;
- 107 deduplicated reader pages in the current Gate 5 candidate manifest.

These counts describe the current local candidate. They do not prove a hosted release and can change when the governed registries change.

## Deliberately outside the public v1 core

The candidate release excludes:

- private AI-chat bodies and private collaboration records;
- credentials, provider-control files, and local machine paths;
- unpublished book manuscripts and private editorial notes;
- raw recordings that have not been reviewed for public release;
- copyrighted source images without a release basis;
- Comparison Wiki verdicts that have not crossed their separate public corridor;
- speculative claims that cannot yet be stated with a responsible evidence boundary.

## Continuing-work backlog

### Before a public v1 release

- Complete the B-series direct-dependency transcript confidence check.
- Re-transcribe only the highest-value noisy recordings needed for public load-bearing claims.
- Re-run the local route and external-link audit after every release-surface change.
- Confirm that public pages contain no local-server URLs, local disk paths, private-source bodies, or unresolved aliases.
- Review the exact v1 candidate manifest and freeze a release hash.
- Build the public reader and verify the hosted bytes and routes after deployment.

### After v1

- Continue atomizing the remaining SAN archive by bounded tranche.
- Expand source maps where new evidence changes a concept's genealogy or tests.
- Add clearer diagrams only after anatomy, caption, provenance, and release review.
- Keep scientific literature current without erasing SAN's distinct hypotheses.
- Add new concept pages when recovered material supports a coherent, testable research object.

## Release meaning

A public v1 release would mean that the bounded core is navigable, source-aware, privacy-reviewed, and honest about its limitations. It would not mean that every SAN note has been read, every hypothesis has been validated, or the Wiki can no longer improve.
