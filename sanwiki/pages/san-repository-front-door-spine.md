# SAN Repository Front-Door Spine

Six files explain how the original Self Aware Networks repository was meant to be read, revised,
and navigated. They are not interchangeable. Together they form a repository operating system:
mission, orientation, chronology, concept routing, editorial backlog, and working memory.

## How the files work together

1. `README.md` tells a reader what the project is trying to become and warns that the archive is a
   heterogeneous open notebook.
2. `00welcome.md` gives the initial reading sequence and explains the note and transcript families.
3. `00changelog.md` provides the strongest repository-native revision chronology.
4. `map.napot.md` routes a central concept across scattered notes and records alternate names.
5. `00todolist.md` records intended but unfinished organization, comparisons, and source cleanup.
6. `00abstractbump.md` preserves transient synthesis that was meant to be movable, but became a
   historically useful source in its own right.

This hierarchy prevents several common mistakes. A task on the todolist is not completed merely
because it is named. A changelog date is not automatically the date an older precursor idea was
first conceived. A map entry is not the source's full argument. A working-memory note is not a
finished manuscript. A README declaration is a statement of project posture, not outside peer
review or scientific validation.

## The golden-corpus correction

The historical README says later editing would separate valuable information from worthless
material. The current governing rule is more careful: every SAN intellectual artifact is retained
and routed. Editorial priority determines whether a source belongs in the narrative spine, a
specialist page, an evidence reserve, a history note, or an outward branch. It does not determine
whether the source survives.

That correction does not rewrite the historical README. The wiki preserves the older statement and
records the current policy as a later editorial rule.

## Provenance boundaries

- First Git date, in-file event date, claimed development date, public recording date, and later
  revision date are separate fields.
- Repository chronology establishes what was present in a commit, not the truth of a scientific
  claim.
- Automatic transcripts need audio and speaker verification before exact quotation.
- The repository's self-description as a preprint or peer-review surface does not equal journal
  peer review by an external institution.
- Later processed wiki pages interpret these sources; the raw files remain controlling for exact
  wording.
